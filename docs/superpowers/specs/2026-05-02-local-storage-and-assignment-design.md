# 로컬 저장 방식 전환 + 전담 배정 알고리즘 설계

## Goal
Supabase 의존성을 제거하고 엑셀+localStorage 기반으로 전환하며,
전담 교사 담당 과목·학년·반·시수를 자동 배정하는 새 탭을 추가한다.
기존 Supabase 버전은 `main` 브랜치에 보존하고 새 버전은 `local` 브랜치에서 개발한다.

## Architecture

- **브랜치**: `local` (main 보존)
- **배포**: Vercel에서 `local` 브랜치를 새 프로젝트로 연결
- **데이터 흐름**:
  1. 앱 시작 → localStorage에서 데이터 복원 (없으면 빈 상태)
  2. 작업 중 모든 변경 → localStorage 자동 저장
  3. 다른 기기 이동 시 → 엑셀 내보내기 → 새 기기에서 업로드
- **제거**: Supabase 클라이언트, 로그인 페이지, 인증 라우팅
- **추가**: 엑셀 가져오기/내보내기, 전역 상태 관리, 전담 배정 탭

## Tech Stack
- React 18, Vite, TailwindCSS (기존 유지)
- `xlsx` (기존 엑셀 내보내기에서 이미 사용 — 가져오기도 추가)
- React Context (전역 상태) 또는 Zustand
- localStorage (자동 저장)
- Supabase 완전 제거

## Part 1: 데이터 저장 방식

### 전역 상태 구조 (appState)
```js
{
  schoolName: string,
  gradeConfigs: [...],      // 학년별 학급수·교시수
  lunchConfig: {...},       // 점심 설정
  subjects: [...],          // 학년별 과목 (is_major 포함)
  teachers: [...],          // 교사 목록
  teacherAssignments: [...],// 전담 배정 결과
  rooms: [...],             // 특별실
  roomBlockedSlots: [...],
  timetableSlots: [...],    // 생성된 전담 시간표
  roomTimetableSlots: [...],
  assignmentSettings: {
    maxMajorSubjectsPerTeacher: 1  // 교사당 주요 과목 최대 수
  }
}
```

### localStorage 자동 저장
- 상태 변경 시마다 `localStorage.setItem('timetable_data', JSON.stringify(appState))`
- 앱 시작 시 복원

### 엑셀 파일 구조 (시트 목록)
| 시트명 | 내용 |
|--------|------|
| 학교설정 | 학교명, 학년별 학급수·요일별 교시수 |
| 점심설정 | 분리점심 여부, 학년별 점심 슬롯 |
| 교사목록 | 교사 코드 |
| 과목설정 | 학년, 과목명, 주당시수, 주요/일반 |
| 전담배정 | 교사코드, 과목명, 학년, 반목록, 주당시수 |
| 특별실 | 특별실명 |
| 특별실차단 | 특별실명, 요일, 교시 |
| 시간표 | 학년, 반, 요일, 교시, 교사코드, 과목명 (참고용) |

### UI 변경
- 로그인 페이지 제거 → 앱 열면 바로 학교 설정 탭
- 레이아웃 우측 상단에 버튼 2개 추가:
  - **엑셀 내보내기** (현재 데이터 전체 다운로드)
  - **엑셀 가져오기** (파일 업로드 → 덮어쓰기 확인 팝업)

## Part 2: 전담 배정 탭

### 탭 순서
학교 설정 → **전담 배정** → 전담 교사 관리 → 특별실 관리 → 전담 시간표 → 특별실 시간표

### 과목 설정 (학교 설정 탭에서 이동)
```
학년 | 과목명 | 주당 시수(반당) | 구분
 3   | 영어   |     3          | [주요▼]
 3   | 과학   |     2          | [주요▼]
 1   | 동아리 |     2          | [일반▼]
```
- 학교 설정 탭의 과목 설정 섹션을 전담 배정 탭으로 이동

### 배정 설정
```
교사 1명당 주요 과목 최대 개수: [1▼]  (1 / 2 / 제한없음)
```

### 알고리즘 로직

**1단계: 담임 시수 계산**
- 각 학년의 주당 전체 교시 수 = 요일별 교시 합계
- 각 학년의 전담 시수 = 해당 학년 모든 과목의 주당 시수 합계
- 담임 시수 = 전체 교시 − 전담 시수
- **제약**: 동학년 담임 시수는 반드시 동일 (과목별 시수가 학년 단위로 동일하게 입력되므로 자동 보장)

**2단계: 교사 목표 시수 계산**
- 전체 전담 시수 합계 = Σ(과목 시수 × 학급 수)
- 교사 목표 시수 = 전체 전담 시수 합계 ÷ 교사 수 (반올림)

**3단계: 배정 단위 생성**
- 배정 단위 = (과목, 학년) 쌍
- 단위당 시수 = 과목 시수 × 해당 학년 학급 수
- 기본 원칙: 교사 1명이 1배정단위 전체 담당

**4단계: 교사에게 배정 단위 할당 (그리디)**
- 주요 과목 먼저 배정 (제약이 강한 것부터)
- 교사당 주요 과목 최대 개수 설정 준수
- 목표 시수에 가장 가까워지는 교사에게 배정
- 배정 후 교사 간 시수 편차가 임계값 초과 시: 특정 배정 단위의 학급을 두 교사가 나눠 담당

**5단계: 학급 배분**
- 기본: 한 교사가 해당 학년 전 학급 담당
- 분리 필요 시: 앞 절반 / 뒤 절반으로 분리 (예: 1~4반 / 5~7반)

### 보장 조건 (알고리즘이 반드시 충족)
- 동학년 담임 시수 완전 동일
- 모든 과목·학년 조합 반드시 배정 (불가능하면 오류 메시지)
- 주요 과목 최대 개수 설정 준수

### 경고 조건 (배정은 되지만 알림 표시)
| 조건 | 기준 |
|------|------|
| 학년 간 담임 시수 편차 | 최대 − 최소 > 2h |
| 전담 교사 시수 초과 | 목표 시수 + 3h 초과 |
| 전담 교사 시수 부족 | 목표 시수 − 3h 미만 |

### 결과 화면 및 반복 조정 워크플로우

```
[자동 배정 실행] 버튼
        ↓
결과 테이블 + 경고 하이라이트 표시
        ↓
조정 방법 2가지:
  A. 입력값(과목·시수·교사수) 수정 → [자동 배정 재실행]
     → "수동 수정 내용이 초기화됩니다" 확인 팝업
  B. 결과 테이블 셀 직접 수정
     → 경고 실시간 재계산
     → 수동 수정 셀은 배경색으로 구분
        ↓
[전담 교사 관리에 적용] 버튼 → 다음 단계로
```

### 결과 테이블 컬럼
| 교사 | 담당 과목 | 학년 | 담당 반 | 주당 시수 | 상태 |
|------|---------|------|--------|---------|------|
| 34영어 | 영어 | 3학년 | 1~7반 | 21h | ✓ |
| 34영어 | 동아리 | 1학년 | 1~7반 | 14h | ⚠️ 초과 |

- 하단에 담임 시수 현황 표 (학년별 담임 시수, 편차 경고)
- 전담 교사 시수 요약 (목표 대비 ±)
