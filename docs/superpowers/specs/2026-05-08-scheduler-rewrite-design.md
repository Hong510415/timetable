# 전담 시간표 자동 생성 알고리즘 — 재설계 스펙

작성일: 2026-05-08
대상 파일: `src/lib/scheduler.js`

---

## 1. 핵심 철학

**"전담교사 입장에서 어떤 시간표 배치가 수업 준비를 효율적으로 만들까"** 를 1순위 기준으로 둔다.

- 전담교사는 같은 과목·자료·준비물을 여러 학급에 반복해서 사용함
- 자료 준비, 교실 세팅, 멘탈 컨텍스트 스위칭의 비용이 시간표 배치에 따라 크게 달라짐
- "같은 학년" vs "같은 과목" 충돌 시 → **같은 과목** 우선 (자료 재활용)
- 같은 과목을 여러 학급에 연달아 가르치는 게 같은 학급을 연달아 가르치는 것보다 일반적으로 더 효율적

## 2. 입력 데이터

| 이름 | 타입 | 설명 |
|---|---|---|
| `gradeConfigs` | `[{grade, num_classes, periods_mon~fri}]` | 학년별 학급 수와 요일별 교시 수 |
| `subjects` | `[{id, name, weekly_hours, is_major}]` | 과목 정의 (테이블에 연속 필드 없음) |
| `subjectSettings` | `{ [subjectName]: {allow: bool, maxCount: number} }` | 과목별 연속 가능 여부 + 하루 최대 시수 (UI에서 설정). 환산: `maxSameDay = allow ? maxCount : 1` |
| `teachers` | `[{id, code, teacher_assignments: [{subject_id, grade, class_num, weekly_hours}]}]` | 교사별 배정 정보 |
| `lunchConfig` | `{split_lunch, lunch_groups: [{grades, slot}]}` | 점심 모드. split_lunch=false면 점심이 시간표 밖 |
| `rooms` | `[{id, name, subjectNames?, teacherIds?}]` | 특별실. subjectNames에 든 과목이 이 방 사용. teacherIds 있으면 화이트리스트 |
| `roomBlockedSlots` | `[{room_id, day_of_week, slot}]` | 특별실 사용 불가 시간 |

## 3. 하드 제약 (Hard Constraints)

위반 시 배치 불가. 모든 하드 제약을 통과한 후보 중에서만 소프트 점수로 선택.

### #1 교사 슬롯 충돌 금지
같은 교사가 같은 (day, slot)에 두 학급 이상 가르칠 수 없다.

### #2 학급 슬롯 충돌 금지
같은 학급이 같은 (day, slot)에 두 수업 받을 수 없다.

### #3 시수 정확 일치
각 (teacher, subject, grade, class)의 `weekly_hours`를 정확히 채운다.

### #4 학급 가용 슬롯 준수
학급의 요일별 교시 수(`periods_X`) 안에서만 배정한다.
점심 분리 모드일 때 해당 학년의 점심 슬롯은 제외한다.

### #5 점심시간 확보 (분리 모드 한정)
- `split_lunch = true`일 때만 적용
- 교사가 모든 점심 슬롯에서 다른 학년 수업하면 본인 점심 못 먹음
- 모든 점심 슬롯들 중 **요일별로 최소 1슬롯**은 비워둬야 한다 (요일별로 다른 슬롯이어도 OK)
- `split_lunch = false` (점심 공통): 점심이 시간표에 안 나오므로 자동 확보됨, 별도 제약 없음

### #6 특별실 사용 가능 시간 준수
- 과목이 특별실 필요 (`subjectNames`로 매핑)할 때, 모든 가능 특별실이 차단된 슬롯에는 배정 불가
- 여러 특별실 중 하나라도 가능하면 그 시간 OK (교집합 방식)

### #7 특별실 교사 화이트리스트
특별실의 `teacherIds`가 비어있지 않으면 그 교사들만 그 특별실 사용 가능.
화이트리스트에 없는 교사는 그 특별실이 필요한 슬롯에 배정 불가.

### #8 과목 끼어들기 금지 (과목 샌드위치 금지)
같은 교사가 같은 요일에 같은 과목의 수업 사이에 다른 과목을 끼울 수 없다.
- 예: 1교시 영어, 2교시 통합, 3교시 영어 → ✗ (영어-통합-영어 sandwich)
- 예: 1교시 영어, 2교시 영어, 3교시 통합 → ✓
- 구현 시 #9(학년 샌드위치)와 함께 다룬다 (둘 다 같은 교사 같은 요일 sandwich 패턴)

### #9 학년 끼어들기 금지 (학년 샌드위치 금지)
같은 교사가 같은 학년의 수업 사이 슬롯에 다른 학년 수업을 끼울 수 없다.
**적용 범위: 같은 학년 안에서만**. 다른 학년끼리는 무관.
- 예: 1교시 5-1, 2교시 6-1, 3교시 5-2 → ✗ (5학년 사이에 6학년 끼어듦)
- 예: 1교시 5-1, 2교시 6-1, 3교시 6-2 → ✓ (5학년 1번뿐, sandwich 없음)

### #10 같은 학급 같은 과목 calendar order
같은 (학급, 과목)의 N번째 블록의 요일은 (N-1)번째 블록의 요일보다 같거나 뒤에 와야 한다.
- 즉 day(block N) ≥ day(block N-1)
- 예: 5-1 영어 3블록 → 월/수/금 ✓ / 월/수/수 ✓ / 월/금/수 ✗
- 구현 시 #9, #11과 함께 다룬다 (모두 패턴/분산 관련)

### #11 같은 학년 같은 과목 패턴 통일
같은 (grade, subject)의 모든 학급은 동일한 배치 패턴을 사용한다.

- **pair 패턴:** 모든 학급이 같은 날 2시간 연속 (요일은 학급마다 달라도 됨)
  - 예: 5-1 월 1-2교시, 5-2 화 3-4교시, 5-3 수 1-2교시 ✓
- **split 패턴:** 모든 학급이 분산 (1시간씩 다른 날)
  - 예: 5-1 월 1교시 + 수 3교시, 5-2 화 1교시 + 목 2교시 ✓

혼용 금지 (5-1만 pair 5-2는 split → ✗)

### #12 같은 학급 + 같은 과목 같은 날 배치 규칙
- `max_consecutive = 1` (연속 불가) 과목 → 같은 학급+같은 과목은 **다른 날에만** 배치. 같은 날 중복 금지(연속/비연속 모두)
- `max_consecutive = 2` (연속 허용) 과목 → 같은 학급+같은 과목 같은 날 배치는 **연속(pair)으로만** 허용. 비연속 같은 날 금지

(이게 #11과 함께 작용해서 같은 학년 안에서 패턴 통일을 강제함)

### #13 교사 요일 부하 균형 (편차 ±2 보장)
교사의 한 요일 수업수 ≤ `ceil(T/5)` (T = 교사 주 총 시수)

- 결과: 가능한 분포는 `{floor, ceil, ceil, ceil, ceil}` 또는 `{ceil×5}` 정도로 자연 균형
- 예: T=19 → cap=4 → {3,4,4,4,4} (max-min=1)
- 예: T=20 → cap=4 → {4,4,4,4,4}
- 사용자 명시: "요일간 편차 ±2 하드 제약"
- 소프트 (e)와 별도 — 소프트는 약한 압박, 하드는 절대 cap

**구현 메모:** 이 제약과 #10(calendar order)이 충돌하지 않게 블록 정렬 시 `totalBlocks` 많은 학급 먼저 처리. 그래야 후속 블록이 늦은 요일에 들어갈 여유 확보.

## 4. 소프트 선호 (Soft Preferences)

하드 제약 통과 후보들 중에서 점수 최대값을 선택. 동점이면 랜덤 타이브레이크.

### (a) 같은 과목 같은 날 클러스터링 (across class) — 가중치 **높음**

같은 교사가 같은 과목을 여러 학급에 가르칠 때, 가능하면 같은 날에 모음.

- 예: 영어전담이 5-1, 5-2, 6-1 영어를 모두 월요일에 → 자료 1회 준비, 멘탈 1회
- 학년이 달라도 같은 과목이면 모이는 게 좋음
- **bonus = +5** per 같은 (교사, 과목) 같은 날 추가 배치

### (b) 인접 슬롯 다른 과목 페널티 — 가중치 **중간**

같은 교사가 같은 날 인접한 두 슬롯에서 **다른 과목**을 가르치면 페널티.

- 예: 1교시 영어, 2교시 통합 → 페널티 (자료/멘탈 컨텍스트 스위치)
- 예: 1교시 영어 5-1, 2교시 영어 5-2 → 페널티 없음 (학년 달라도 OK)
- **penalty = −3** per 인접 슬롯 다른 과목 발생

### (c) 같은 학년 같은 과목 같은 날 보너스 — 가중치 **중간**

큰 학교(전담 1명당 학년 적음)에서만 실질적 의미. 작은 학교에서는 자동으로 만족 못 해도 페널티 미미.

- 예: 5-1, 5-2, 5-3 영어 모두 월요일 → (a) 보너스 + (c) 추가 보너스
- (a) 만족 가능한 큰 학교에서 타이브레이커로 작동, 작은 학교에서는 영향 없음
- **bonus = +2** per 같은 (학년, 과목) 같은 날

### (d) 학급 회차별 target 요일 분산 — 가중치 **중간**

(e) 교사 부하 균등을 잘 작동시키기 위한 보조 메커니즘. 학급 단위로 같은 과목 블록을 균등한 요일에 배치 유도.
- **목적:** (e)의 보조. 이거 없이 (e)만 있으면 알고리즘이 요일 균등 잘 못 함 (이전 시도에서 실패)
- **공식:** 한 학급 같은 과목의 N번째 블록 → target 요일 = `round(N × 4 / (블록수 − 1))`
- 예: 블록 2개 → 월/금
- 예: 블록 3개 → 월/수/금
- 예: 블록 4개 → 월/화/목/금
- 단일 블록은 (분모 0이라) 제약 없음
- **penalty = −2 × |actual_day − target_day|** per 블록

**참고:** 이 (d)가 잘 작동하면 (e)와 같은 결과를 낳음. 만약 향후 (e)만으로도 충분하다고 판명되면 (d)는 제거 가능.

### (e) 교사 요일별 수업 부하 균형 — 가중치 **중간**

교사 입장에서 한 주의 수업이 특정 요일에 몰리지 않게 균등 분산. **(d)의 진짜 목적이자 직접 조건.**
- **대상:** 교사 단위
- **계산:** 교사 주 총 시수 T → 일 평균 = T/5
- **페널티 식:**
  - **penalty = −2 × max(0, 배치 후 day_count[teacher][day] − ceil(T/5))**

**예시:** 영어전담 주 15시간, 평균 3시간, ceil=3
- 현재 월 3, 화 1, 수 3, 목 2, 금 2 (총 11시간 배치)
- 다음 1시간을 월에 → 월 4 → 3 초과 → 페널티 −2
- 다음 1시간을 화에 → 화 2 → 평균 미만 → 페널티 0

**(a)와의 관계:** (a)는 같은 과목을 같은 날에 모으자 (+5), (e)는 그 결과로 한 날에 몰리는 걸 억제 (−2). 가중치 차이로 (a) 우선 + 한계 도달 시 (e)가 멈춤.

### (f) 학급 요일별 전담 수업 부하 균형 — 가중치 **중간**

학급 입장에서 전담 수업이 특정 요일에 몰리지 않게 균등 분산.
- **대상:** 학급 단위 (해당 학급의 모든 전담 과목 합산)
- **이유:** 학급 입장에서도 어떤 날 전담 0시간, 다른 날 5시간이면 학생·담임 부담
- **계산:** 학급의 주 전담 총 시수 C → 일 평균 = C/5
- **페널티 식:**
  - **penalty = −2 × max(0, 배치 후 class_day_count[grade][class][day] − ceil(C/5))**

**예시:** 5-1 전담 주 7시간 → 평균 1.4, ceil=2
- 현재 월 2, 화 0, 수 2, 목 2, 금 1 → 다음 배치는 화/금 선호 (월수목은 이미 ceil 도달)

### (g) 학년 간 회차 진행 정렬 — 가중치 **낮음**

다른 학년끼리도 회차(블록 인덱스) 진행이 비슷하게. 한 학년이 너무 앞서가지 않게 억제.
- **이유:** 4학년 블록 3까지 끝났는데 5학년 블록 0부터 시작하면 큰 격차 → 라운드로빈 정신 위배
- **트래킹:** `block_progress[grade]` = 해당 학년에서 지금까지 배치된 최대 블록 인덱스
- **페널티 식:** 현재 배치 대상 (grade, block N)에 대해
  - **penalty = −1 × max(0, N − min(block_progress[다른 학년]))**
- 작은 가중치라 (a)~(f)와 충돌 시 양보, 동점일 때 타이브레이커

### (h) 교사 같은 날 슬롯 gap 최소화 — 가중치 **낮음**

같은 교사가 같은 날 수업할 때 슬롯이 연속이 좋고 떨어진 게 안 좋음.
- 예: 1-2-3교시 연속 ✓ vs 1교시 + 5교시 ✗
- **penalty = −1** per gap slot (교사 첫 슬롯 ~ 마지막 슬롯 사이 빈 슬롯 수)

## 5. 점수 계산식

```
score = 0
  + 5 × (same subject same day count for this teacher)         // (a)
  − 3 × (adjacent different subject count for this teacher)    // (b)
  + 2 × (same grade+subject same day count for this teacher)   // (c)
  − 2 × |actual_day − target_day(N)|                           // (d)
  − 2 × max(0, teacher_day_count[d] − ceil(T_teacher/5))       // (e)
  − 2 × max(0, class_day_count[g][c][d] − ceil(T_class/5))     // (f)
  − 1 × max(0, block_N − min(other_grades_block_progress))     // (g)
  − 1 × (gap slot count for this teacher this day)             // (h)
```

배치 후보 중 `score` 최대값 선택. 동점이면 랜덤.

## 6. 알고리즘 흐름

### 단계 1: 전처리
- 학년/학급별 요일별 가용 슬롯 계산
- 과목별 특별실 매핑 + 차단 슬롯 정리
- 과목별 `maxSameDay` 정리
- 특별실별 교사 화이트리스트 정리

### 단계 2: 패턴 결정 (#9 + #10 + #11 함께 처리)
각 `(grade, subject)` 조합에 대해 pair vs split 결정 — 모든 학급이 동일 패턴:

- `weekly_hours = 1` → split (단일)
- `weekly_hours = 2` AND `max_consecutive ≥ 2` → pair (선호) 또는 split
- `weekly_hours = 2` AND `max_consecutive = 1` → split 강제
- `weekly_hours = 3` AND `max_consecutive ≥ 2` → pair 1개 + single 1개 (혼합 단위)
- `weekly_hours = 3` AND `max_consecutive = 1` → split 3개

(상세 규칙은 implementation plan에서 결정)

### 단계 3: 블록 단위 라운드로빈 배치
- **블록(block):** pair=2시간 묶음 / single=1시간 묶음
- **회차(round):** 모든 학급의 N번째 블록을 한 번에 처리
  - 1회차 = 모든 학급 1번째 블록 / 2회차 = 모든 학급 2번째 블록 / ...
  - 회차 안에서 학급 순서는 무관 (사용자 명시)
- 회차 순서대로 블록을 꺼내며 배치
- 각 블록을 배치할 때:
  1. 모든 (day, slot) 후보 생성
  2. 하드 제약 #1~#12 모두 통과하는 후보만 남김
  3. 후보 없으면 미배정으로 표시
  4. 후보가 있으면 score 최대값 선택

### 단계 4: 결과 변환
- `result` 객체 → DB 저장 형식 `rows`로 평탄화
- 미배정 unit은 `errors`로 보고

---

## 7. 출력 형식

```javascript
buildSchedule(...) → {
  result: { [grade]: { [classNum]: Array<5 days> of Array<totalSlots> of (cell|null) } },
  errors: [{ grade, classNum, teacherId, subjectId, unassigned }],
  gradeLunchSlot: { [grade]: slotIndex },
  totalSlots: number
}

flattenResult(result, gradeLunchSlot, totalSlots) → {
  rows: [{ grade, class_num, day_of_week, slot, teacher_id, subject_id, room_id?, is_unassigned }],
  errors: []
}
```

cell 형식: `{ teacherId, subjectId, roomId? }`
